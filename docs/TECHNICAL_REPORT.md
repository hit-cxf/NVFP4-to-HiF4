# NVFP4 到 HiF4 的校准感知量化：技术报告

> 对应源码：[`solution.py`](../solution.py)，选定版本 `09281502`。本文解释已公开实现，不包含赛事任务书或测试数据。安装与调用步骤见 [中文 README](../README.md)；[English README](../README.en.md) 也提供完整用法。

## 摘要

本方案面向 NVFP4 表示的 Linear 与 Attention 操作，将输入数值转换为 HiF4 分层表示。核心思路是在**不改变理想算子输出**的前提下，先对成对操作数做等价变换，再利用校准数据估计量化误差对输出的影响，决定尺度、通道顺序和有限次数的离散修码。Linear 关注矩阵乘法误差，Attention 分别处理 Q/K 对 logits 与输出的影响，以及 V 的序列窗口残差。实现为 CPU eager PyTorch 参考代码；昇腾端的模型加载、HiF4 二进制打包与 NPU 算子不在本仓库内。

## 1. 问题与符号

源码接收**已解包为数值张量**的 NVFP4 输入 `quant` 以及对应尺度 `scale`。若最后一维宽度为 `C`，则 `scale` 的最后一维为 `C/16`。解码先做逐 16 元素共享尺度的乘法，再将结果转为 BF16：

```text
X = BF16(quant × repeat_each(scale, 16))
```

输出以每 64 个元素为一组。每组有一个 E6M2 根尺度 `r`；组内采用 8×2×4 的层级结构，两层离散倍率分别记为 `s₂, s₃ ∈ {1, 2}`。重建值为

```text
x̂ = r × s₂ × s₃ × sign × mant,
sign ∈ {-1, 0, 1}, mant ∈ {0, 0.25, …, 1.75}。
```

输出是 `scale_factor`、`scale_lv2`、`scale_lv3`、`sign`、`mant` 五个张量字段，尚不是昇腾硬件直接消费的打包字节流。共享的编码逻辑会对 E6M2 根尺度及子尺度候选计算重建误差；不同操作使用各自的误差权重和修码策略。

## 2. Linear：让量化误差对齐矩阵乘法

### 2.1 配套变换

设解码后的激活为 `A`、权重为 `W`，目标算子为 `Y = A Wᵀ`。对同一通道维度应用正交变换 `R`、正对角尺度 `B` 及相同的通道置换 `P`，可以组成

```text
A′ = A R B P H,
W′ = W R B⁻¹ P H,
A′ W′ᵀ = A Wᵀ  （精确算术下）。
```

这里 `R` 是从校准激活统计中确定的最多两次 Householder 反射，`B` 由权重和激活的逐通道 RMS 构造，`P` 组合通道重排，`H` 为分组 H64 正交变换。实现还用校准样本的幅值关系安排组内通道顺序，以改变有限精度量化所见的数据分布。输入宽度或校准条件不满足 Householder 路径时，源码使用不含这两次反射的兼容路径；因此两次反射不是每个输入的必经步骤。

上式描述的是未量化时的等价关系。实际计算使用量化后的 `A′` 与 `W′`；单独重建的权重或激活处在变换坐标系中，不能逐元素当作原张量的近似。

### 2.2 校准权重与修码

把变换后的校准激活构成分块 Gram 矩阵 `G ≈ A′ᵀ A′ / N`。若权重量化误差为 `ΔW`，相应输出误差的二次近似为

```text
L_W = tr(ΔW G ΔWᵀ)。
```

源码将 Gram 与其对角部分混合以稳定修码，对 HiF4 有限尾数编码进行候选搜索、分块误差传播和坐标更新；仅接受能降低所用二次代价的候选。在宽块路径上还比较多种权重量化候选。校准阶段保存所需的尺度、置换、权重敏感度和低秩信息，供在线激活量化使用。

在线路径先复用同一套配套变换，再按权重敏感度选择 HiF4 尺度和尾数，对离散编码做局部修正。校准还在少量组级根尺度倍率候选中比较输出相关代价，最终重新比较组合方案与原方案，再决定是否保存倍率。上述优化针对近似输出误差；它不保证每个单独元素都比普通最近邻舍入更精确。

## 3. Attention：保持 logits 语义并控制输出误差

### 3.1 Q/K 的等价结构

对于每条序列，K 先减去其时间维均值 `μ_K`。将 Q 乘以正尺度 `b`、K 除以 `b`，再给两者施加相同正交变换 `H`：

```text
Q′ = H(Q ⊙ b),       K′ = H((K − μ_K) ⊘ b)。
```

此式中的 `H(·)` 表示沿特征维的正交变换。在未量化的内积中，互逆尺度和共同正交变换相互抵消。`Q(K − μ_K)ᵀ` 相比 `QKᵀ`，对每个 query 只少了一个与 key 位置无关的常数，因此 softmax 概率保持不变。GQA 的 Q 头复用其对应 KV 头的尺度。源码对 256 维 head 使用 H256，对其他 64 对齐的 head 使用分组 H64；不满足条件时保留原特征坐标。

初始 `b` 来自 Q/K 的均方统计。进一步的尺度校准使用 Q、K、V 样本形成输出敏感度统计，并同时考虑 Full 与 causal 注意力。候选尺度只有在校准代价改善时才被采用。V 在这里用于计算敏感度；在线量化 Q/K 时不会读取未来 V 或参考输出。

### 3.2 对角加低秩的误差度量

源码以校准注意力概率构造 Q/K 的输出敏感度近似矩阵，对称化后取其主特征方向，并保存一个对角项和 rank-3 低秩项。在线修码使用的近似代价可写作

```text
L(e) ≈ Σ_j d_res,j e_j² + ||Uᵀ e||₂²，
d_res = max(d − diag(UUᵀ), ε)。
```

其中 `e` 是量化残差，`U` 来自最多三个主特征方向；实现使用压缩的 INT8 向量及对应尺度恢复 `U`。这个代价近似衡量残差对 Attention 输出的影响，不能视作真实模型损失的精确 Hessian。

在 Q 的校准阶段，每条序列分层抽取最多 16 个 token，估计各维度可获得的修码收益，并以“新增残差覆盖”为准则选取 16 个**候选位置**。然后按与实际在线一致的两轮离散修码计算校准残差；仅当建议位置优于原位置时保存新索引。在线 Q/K 各进行两轮修码，每轮选使近似代价下降的离散坐标改动。16 是可选位置数量，不代表每个 token 必然修改 16 个维度。

### 3.3 V 的窗口残差反馈

V 不保存校准状态。在线量化先搜索 HiF4 根尺度和层级尺度、得到初始重建 `V̂`，再计算残差 `E = V − V̂`。每个长度为 64 token 的窗口内，对相同通道求残差均值 `μ_E`，按

```text
V_corr = V + 0.2 μ_E
```

修正后在**原已确定的尺度树上**重新舍入尾数。末尾不足 64 token 的窗口单独求均值。该反馈针对序列窗口的系统性偏差，不是对每个元素单独重新搜索根尺度。

## 4. 实现边界与复现

`solution.py` 只导入标准库 `math` 与 `torch`。校准状态从对应接口返回，在线接口按角色读取，处理时按块拆分张量以控制临时内存。源码中的 chunk 大小、在线张量分配和预处理方式是实现细节；整场执行用时还包含不同接口及评测流程，不能据此推导单个算子或模型在昇腾 NPU 上的延迟。
